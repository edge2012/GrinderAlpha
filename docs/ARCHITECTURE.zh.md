# 架构

InvestmentOS 把**确定性计算**和 **LLM 判断**分开。两层，分工严格。

## 系统总览

```
                ┌─────────────────────────────────────────────┐
                │               决策流水线                     │
                │                                             │
  行情数据 ─────┤  宏观 → 姿势 → 估值 → 买入点                  │
                │     │       │       │         │             │
                │     ▼       ▼       ▼         ▼             │
                │  ┌─────────────────────────────────────┐    │
                │  │   第 1 层：确定性引擎                │    │
                │  │   (engine/)                         │    │
                │  │   · market_state_engine   5 姿势     │    │
                │  │   · valuation_engine      PE/PB 分位 │    │
                │  │   · bottom_accelerator    DCA 倍率   │    │
                │  │   · buy_point_engine      插件化      │    │
                │  │   · cboe_options / options_estimator │   │
                │  │   · support_levels                   │    │
                │  └─────────────────────────────────────┘    │
                │                    │                        │
                │                    ▼                        │
                │  ┌─────────────────────────────────────┐    │
                │  │   第 2 层：LLM 辩论引擎              │    │
                │  │   (debate_engine/)                   │    │
                │  │   多空辩论 → 裁判 → 交易员            │    │
                │  │   → 风控辩论 → PM 决策               │    │
                │  └─────────────────────────────────────┘    │
                │                    │                        │
                │                    ▼                        │
  决策 ─────────┤  记录 → 复盘（回顾）                        │
                └─────────────────────────────────────────────┘
```

## 第 1 层：确定性引擎（`engine/`）

纯计算——规则、数学、回测。没有 LLM，没有第三方依赖（仅标准库）。

| 引擎 | 职责 |
|------|------|
| `market_state_engine.py` | 把 15+ 个指标聚合成 5 种市场姿势 |
| `valuation_engine.py` | 分类 PE/PB 分位估值 |
| `bottom_accelerator.py` | 对回撤底部拟合对数线性趋势线 → DCA 倍率 |
| `buy_point_engine.py` | 把标的路由到对应的方法论插件 |
| `cboe_options.py` | 真实 CBOE 期权链 + 流动性门禁 |
| `options_estimator.py` | 纯 Python Black-Scholes（兜底） |
| `support_levels.py` | 从历史回撤底部提取支撑位 |
| `macro_pipeline.py` | 7 指标宏观 Regime 分类 |

BuyPointEngine 是插件模式最干净的示例：顶层只定义路由和输出 schema，`methodologies/` 里有五套独立实现，按「市场 × 标的类型」分。

## 第 2 层：LLM 辩论引擎（`debate_engine/`）

一条多智能体流水线，把原始数据变成结构化决策。引擎刻意**自包含**——它接收已格式化的 `AnalysisInput`，返回 `DebateResult`，不 import 任何确定性引擎。

### 流水线

```
AnalysisInput
    │
    ├── 情景辩论  （多 vs 空，最多 2 轮）
    │       └── 情景裁判  （选出更站得住的一方）
    │
    ├── 交易员  （模拟仓位设计）
    │
    ├── 风控辩论  （激进 / 保守 / 中性）
    │
    └── 组合经理  （最终建议）
            │
            ▼
       DebateResult
```

### Agent 角色

| Agent | 职责 |
|-------|------|
| 多头 / 空头 | 就交易论点做正反方攻辩 |
| 情景裁判 | 权衡两方，判定更强的一方 |
| 交易员 | 提出具体仓位方案 |
| 风控辩手 | 从三种风险姿态挑战方案 |
| 组合经理 | 把一切综合成最终决策 |

### 关键设计决策

1. **先影子模式。** 辩论先与基线并行运行，验证有效后才替换基线——数据驱动的灰度上线。
2. **分层模型。** 裁判/PM 节点用更强的模型（`deepseek-v4-pro`），辩手用更快的（`deepseek-v4-flash`）。按角色平衡成本与质量。
3. **上下文压缩。** 压缩器总结前面的轮次，把上下文窗口控制在 16K token 以内。
4. **自包含。** 不依赖确定性引擎——LLM 层可独立替换、独立测试。
5. **LLM 只给建议，不下单。** 输出是结构化的 `DebateResult`，从来不是交易指令。

## 决策闭环

整个系统是一个闭环：

```
宏观 Regime（按月）
  → 市场姿势（按日）
    → 买入点扫描（按周）
      → 期权结构设计（逐标的）
        → 决策记录
          → 复盘（按月，胜率 + 决策质量）
```

每个信号在可能的地方都附带回测证据。闭环的目的不是预测市场，而是让每一个决策**可复现、可复盘**。
